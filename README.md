# ESP32-ELRS-Rover

Ровер на ESP32-S3 (YD-ESP32-S3 N16R8) з керуванням через ExpressLRS/CRSF. ESP-IDF v6.1, C. Танковий привід: два борти по два колеса,
енкодери на кожному колесі, регулятор швидкості бортів, чотири далекоміри VL53L0X, світло, зумер, вбудований RGB-індикатор плати.

## Що вміє ровер

- Їде за правим стіком пульта (тяга й поворот), озброюється тумблером (канал 5), тримає швидкість бортів регулятором.
- Зупиняється при втраті звʼязку довше за 0.5 с, при напрузі акумулятора нижче 6.0 В і перед перешкодою (стан OBSTACLE_HOLD).
- Повертає на пульт напругу акумулятора (телеметрія) і показує стан утримання звуком, кольором індикатора й блиманням світла.
- Консоль через USB: стан, команди руху (стендовий режим), світло, зумер, енкодери, регулятор, далекоміри.

## Структура репозиторію

- `docs/` — контекст заліза й прошивки (`01-ASSEMBLY-BRINGUP.md`, `02-FIRMWARE-CONTEXT.md`), конституція (`constitution.md`),
  журнал вимірювань (`measured.md`), блок-схема (`architecture.md`), чекліст самоперевірки (`self-check.md`), дорожня карта
  (`roadmap.md`), специфікації фаз у `docs/features/<фаза>/`.
- `kicad-rover/` — схема й плата (лише читання).
- `main/`, `components/` — прошивка. Кожен компонент ділиться на `<name>_core.c` (чиста логіка, без ESP-IDF) і `<name>_hal.c`.
- `test/host/` — хостові тести чистої логіки і перевірки правил проєкту.
- `tools/bringup/` — діагностичні прошивки P0–P7 (результати — у `docs/measured.md`).

Усі номери ліній GPIO — лише в `components/board/include/board_pins.h`.

## Збірка, прошивка, тести

Збірка (потрібне середовище ESP-IDF v6.1):

```bash
source ~/.espressif/tools/activate_idf_v6.1.sh
idf.py build
```

Прошивку на плату робить Розробник через розширення ESP-IDF у VS Code (ціль `esp32s3`); агент лише збирає. Після прошивки відкрити
монітор, консоль відповідає на `help`.

Хостові тести й перевірки правил (звичайний gcc, без плати):

```bash
test/host/run_tests.sh
```

Опис перевірок — у `test/host/README.md`.

## Інтерфейси

### Консоль (USB)

Повний список — команда `help`. Права команд залежать від стану автомата (`status` показує стан і історію переходів).

| Команда | Призначення |
|---|---|
| `help`, `status` | довідка; стан, час роботи, пам'ять, причина скидання, сховище, світло, індикатор, пульт, **час кроку керування**, енкодери, історія переходів |
| `arm`, `drive <тяга> <поворот>` | озброєння і рух (`drive` діє 2 с) — з консолі лише в стендовому режимі, до появи пульта |
| `disarm` | роззброєння — у будь-якому стані |
| `light`, `beep` | світло й зумер: `light` у DISARMED (в ARMED лише `light head`), `beep` у DISARMED і ARMED; в OBSTACLE_HOLD обидві відхиляються |
| `enc [reset]` | знімок енкодерів |
| `pid ...` | регулятор швидкості бортів |
| `tof [reinit]` | далекоміри, сектори, поріг; `reinit` лише в DISARMED |
| `reboot`, `wdt-test` | службові (лише в безпечних станах) |

### Пульт

Канали CRSF: 1 — поворот, 2 — тяга, 5 — ARM/DISARM (тумблер), 8 — трипозиційний перемикач, за P5 призначений під фари (у прошивці поки не використовується; докладно: `docs/02-FIRMWARE-CONTEXT.md` §1.3 і `docs/measured.md`).

### Телеметрія на пульт

Раз на 200 мс ровер надсилає кадр датчика батареї CRSF: **напруга з розв'язністю 0.1 В**. **Струм, ємність і відсоток заряду нульові
й означають «немає даних»** (датчиків немає): пульт може показувати «0 А» чи «0 %» — це не вимір. Якщо свіжого виміру напруги немає,
кадр не надсилається. На пульті датчик має знайтися автоматично (на модулі передавача співвідношення телеметрії не «вимкнено»).

### Індикація станів

| Стан | Зумер | Індикатор плати | Світло |
|---|---|---|---|
| DISARMED | короткий сигнал на вході | погашений | задні ліхтарі червоні, фари вручну |
| ARMED | короткий сигнал на вході | погашений | фари автоматично, задні ліхтарі: жовтий уперед, зелений назад |
| OBSTACLE_HOLD | подвійний біп на вході та на виході в ARMED | **жовтий** | передній сектор зайнятий — блимають фари; задній — блимають задні ліхтарі |
| FAILSAFE | сигнал на вході, писк кожні 2 с | червоний | задні ліхтарі блимають червоним |

## Безпека

Інваріанти (конституція, п. 7): STBY піднімається тільки в стані руху й свідомо; втрата кадрів CRSF довше за 0.5 с — ШІМ у нуль і
STBY вниз; перша операція на шині I²C — запис нуля в розширювач; напруга нижче 6.0 В — мотори не запускаються. Телеметрія й індикація
їх не змінюють і не затримують керування.
