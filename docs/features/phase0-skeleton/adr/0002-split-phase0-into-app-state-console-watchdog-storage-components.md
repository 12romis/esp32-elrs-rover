# 0002 — Розбити код фази 0 на компоненти app_state, console, watchdog і storage

- **Status:** Accepted
- **Date:** 2026-10-17
- **Deciders:** Розробник проєкту + Claude (сесія design, 2026-10-17)

## Context

Документ 02 §6.4 кладе машину станів у `main/app_states.c`, а консоль — у компонент `telemetry`. Компонент ESP-IDF не може залежати від `main/` (залежності йдуть від `main` до компонентів), а фази 1–3 (`drive`, `ui`, `crsf`) читатимуть і змінюватимуть стан автомата. Пункт 6 конституції вимагає для кожного компонента пару `<name>_core.c` + `<name>_hal.c`, а хостові тести збираються з `_core.c`. Нині `main/app_states.[ch]` — чиста логіка в `main/`, не покрита тестами.

## Decision drivers

- Пункт 6 конституції: core без заголовків ESP-IDF, HAL окремо.
- Фази 1–3 потребують стану з інших компонентів (залежність від `main/` неможлива).
- Мала поверхня змін: S-розмір, 1 фіча.

## Considered options

1. **Нові компоненти** — `components/app_state`, `components/rover_console`, `components/watchdog`, `components/storage`, кожен із `_core.c` + `_hal.c`; `main/` лишає лише `app_main` (ініціалізація й старт задач).
2. **За документом 02 §6.4 у фазі 0, перенесення пізніше** — машина станів у `main/` (`app_states_core.c` + `_hal.c`), консоль у `components/telemetry`; у фазі 1, коли стан знадобиться `drive`, вона переїжджає в компонент.

## Decision outcome

**Chosen:** варіант 1. Стан доступний будь-якому майбутньому компоненту через `REQUIRES app_state`; консоль залежить від `app_state`, але не від `watchdog` і `storage` — потрібні їй дії передаються структурою колбеків від `main` (інверсія залежності). Ідентифікатори `app_state_t`/`APP_STATE_*` лишаються без перейменування. Компонент консолі називається `rover_console`, а не `console`: компонент `console` (esp_console) уже існує в ESP-IDF, і однойменний компонент проєкту його підміняє та ламає збірку (виявлено під час T3). Дерево в документі 02 §6.4 дописується (розбіжність озвучено в handoff; сам документ агент не змінює без вказівки).

## Consequences

**Positive**
- Стан спільний для фаз 1–3 без перекручувань залежностей.
- Кожна частина логіки покривається хостовими тестами окремо; HAL лишається тонким.

**Negative**
- Перенесення пізніше коштувало б міграції файлів у фазі 1; тому відхилено на користь одразу правильного місця.
- Чотири нових каталоги для фази, що містить мало коду; частина `_core.c` (наприклад, `watchdog`, `storage`) дуже мала.
- Відхід від дерева документа 02 §6.4 потребує оновлення цього документа.

**Neutral**
- `telemetry` лишається заглушкою до фази 7; консоль можна пізніше перенести туди, якщо захочеться.
