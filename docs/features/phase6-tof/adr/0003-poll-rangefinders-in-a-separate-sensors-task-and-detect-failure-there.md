# 0003 — Poll rangefinders in a separate sensors task and detect failure there

- **Status:** Accepted
- **Date:** 2026-10-21
- **Deciders:** Розробник, Агент (design, рівень easy)

## Context

Чотири далекоміри опитуються по спільній шині раз на 50 мс (документ 02 §6.1). Один справний обмін триває кілька мілісекунд, а обмін з відʼєднаним чи завислим датчиком може тривати до таймаута. Такт `control` (20 мс, core 1) такої затримки не має права мати (spec §6: затримка «кадр → борти» ≤ 20 мс). Треба вирішити, де виконується опитування і як виявляється відмова, зокрема зависання самої задачі опитування.

## Decision drivers

- Відмова датчика не зупиняє й не вішає прошивку (spec AC-06, AC-07, QG-3).
- Затримка кроку керування ≤ 20 мс максимум.
- Періодичні задачі — `vTaskDelayUntil`; хостові тести логіки без плати.
- Запас вільної памʼяті ≈ 8.6 кБ до порога 345000 байт (spec §6).
- Документ 02 §6.1 уже приписує задачу `sensors` (prio 3, core 0, 50 мс), а Task WDT за §5 мають усі періодичні задачі.

## Considered options

1. **Окрема задача `sensors` (core 0, prio 3, 50 мс):** читає датчики, веде фільтр, сектори й відмови в `tof_core`, публікує знімок під `portMUX`; завислу задачу `control` бачить за віком знімка.
2. **Опитування в кроці `control`:** шина й таймаути потрапляють у такт керування.
3. **Опитування в існуючій задачі `ui` (core 0, 100 мс):** такт 100 мс не дає 50 мс і змішує світло з вимірюванням.
*Окреме рішення власника (Decision override у SAD §1):* `sensors` не підписується на Task WDT попри документ 02 §5; перезавантаження на ходу вважається гіршим за втрату захисту з попередженням.

## Decision outcome

**Chosen:** варіант 1. Затримка шини лишається на core 0; `control` лише копіює знімок і за віком (> 250 мс або `valid == false`) розуміє, що сектори не охороняються. Відмова датчика — 250 мс без валідного відліку (відлік «поза діапазоном» валідний), діагностується в `tof_core`; таймаут транзакції в циклі 10 мс; опитування неблокувальне. Повернення датчика — лише команда `tof reinit` у DISARMED, яку виконує та сама задача (вона одна володіє пристроями шини); на час команди (≤ 3 с) опитування решти призупиняється, бо ініціалізація датчика містить очікування до 500 мс (spec AC-08 послаблено власником). Стек задачі 4096, у Task WDT не підписана.

## Consequences

**Positive**
- Збій шини чи датчика не торкається кроку керування; завислу `sensors` видно як застарілий знімок.
- Уся діагностика — чиста логіка в `tof_core`, тестується на хості.

**Negative**
- Ще одна задача і ≈ 4.6 кБ внутрішньої памʼяті (стек, пристрої шини, знімок).
- Завислу `sensors` ніхто не перезапускає: захист вимкнений, доки Розробник не перезапустить плату.

**Neutral**
- Після п'яти циклів, у яких не відповів жоден датчик, задача скидає шину (як `ioexp`).
- Переміщення опитування в інше ядро чи пріоритет не змінює `tof_core`.
