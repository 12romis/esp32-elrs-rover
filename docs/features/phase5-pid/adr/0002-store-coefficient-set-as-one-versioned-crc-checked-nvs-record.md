# 0002 — Store the coefficient set as one versioned CRC-checked NVS record

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** Розробник, Агент (design, рівень easy)

## Context

Набір коефіцієнтів (Kp, Ki, Kd, темп розгону) і режим регулятора мають переживати перезапуск (spec US-04). Це перші дані, які прошивка зберігає в розділі NVS (компонент `storage` фази 0 лише ініціалізує його). Формат запису переживає перепрошивки, тож змінити його пізніше означає міграцію або втрату підібраного набору.

## Decision drivers

- Неповний чи пошкоджений запис відкидається повністю, жодне число з нього не завантажується (spec AC-07).
- Режим зберігається разом із числами (spec AC-06, «Поведінка регулятора»).
- Збій запису не ламає сеанс (spec AC-08).
- Перевірка запису тестується на хості (spec AC-18; конституція, п. 6).

## Considered options

1. **Один blob із магічним числом, версією і CRC32** — простір `pid`, ключ `set`; кодування й перевірка в `pid_core`.
2. **Окремий ключ на кожне число** — пʼять ключів, записаних послідовно й зафіксованих одним `nvs_commit`.

## Decision outcome

**Chosen:** варіант 1. Запис атомарний: обрив живлення чи збій дають або старий, або новий запис цілком, а пошкодження, чужа версія чи неповний розмір ловляться однією перевіркою в core. У варіанті 2 частково записаний набір (частина нових, частина старих чисел) виглядає повним, і AC-07 його не відловить.

## Consequences

**Positive**
- AC-07 перевіряється хостовим тестом над байтами запису (повний, пошкоджений, неповний, відсутній, інша версія).
- Одна операція запису й читання в HAL.

**Negative**
- Зміна одного числа перезаписує весь запис (кілька десятків байтів — несуттєво).
- Новий формат (додаткове поле) потребує нової версії; без правила міграції старий запис відкидається як «не налаштований» (прийнятий борг, sad.md §11).

**Neutral**
- Шаблон «версійований запис із CRC32» можна повторити для інших налаштувань (наприклад, калібрування напруги), якщо вони переїдуть у NVS.
