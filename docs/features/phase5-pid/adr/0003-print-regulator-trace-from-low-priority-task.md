# 0003 — Print the regulator trace from a low-priority task

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** Розробник, Агент (design, рівень easy)

## Context

Трасування регулятора — 10 рядків за секунду в ARMED із середніми за 100 мс (spec AC-05, «Поведінка регулятора»). Форматування чисел із плаваючою комою і вивід через USB-Serial-JTAG можуть блокувати задачу, коли монітор не встигає читати. Треба вирішити, яка задача друкує, щоб такт керування не спотикався.

## Decision drivers

- Затримка «кадр пульта → борти» ≤ 20 мс максимум, зокрема з увімкненим трасуванням (spec §6).
- 100 ± 2 рядки за 10 с (spec AC-05).
- Періодичні задачі — лише `vTaskDelayUntil` (конституція, п. 14); нові задачі підписані на Task WDT.

## Considered options

1. **Окрема задача `pid_trace`** — prio 1, core 0, 100 мс; `control` лише накопичує суми й публікує кадр під `portMUX`.
2. **Друк прямо в `control` кожен 5-й такт.**

## Decision outcome

**Chosen:** варіант 1. Повільний USB блокує лише задачу трасування на ядрі 0, а `control` робить кілька додавань і одну публікацію кадру. Варіант 2 переносить форматування й вивід у задачу керування і може вивести затримку за 20 мс саме тоді, коли Розробник налаштовує регулятор.

## Consequences

**Positive**
- Такт керування не залежить від консолі.
- Середнє за 100 мс рахується в `control` з точних значень кожного такту.

**Negative**
- Ще одна задача: стек ≈ 3 КБ внутрішньої памʼяті і підписка на Task WDT.
- Під важким виводом рядок може запізнитися чи бути пропущеним (кадр перезаписується новим) — це враховує допуск 100 ± 2.

**Neutral**
- Ту саму задачу можна використати для інших потокових виводів, але для фази 7 (телеметрія) це окреме рішення.
