# 0003 — Bring Wi-Fi up and down per delivery attempt in a dedicated core 0 task that yields to arming

- **Status:** Accepted
- **Date:** 2026-10-22
- **Deciders:** Розробник, Агент (design, рівень easy)

## Context

Spec A13–A15, A18: радіо тільки в DISARMED, одразу вимкнути після спроби, озброєння має пріоритет, ліміт спроби 30 с. Керування й приймач — на core 1, решта разом із Wi-Fi-стеком — на core 0 (документ 02 §6.1). Автомат станів не має колбеків, лише `app_state_get()` (опитування). Документ 01 §5.4: піки Wi-Fi можуть просаджувати 3.3 В при низькій шині +5 В.

## Decision drivers

- Радіо ніколи не вмикається поза DISARMED; Wi-Fi вимкнено після 100 % спроб (spec §6).
- Жоден такт керування, зумер, світло чи консоль не чекають мережі (spec AC-19).
- Вільна памʼять після спроби не менша за значення до спроби мінус 4096 байт (spec §6).

## Considered options

1. **Окрема задача `report` (core 0, низький пріоритет): повний цикл `esp_wifi_init` → підключення → публікація → `esp_wifi_stop`/`deinit` на кожну спробу; перериває спробу, якщо `app_state_get()` перестав бути DISARMED** (перевірка не рідше ніж раз на 100 мс; I/O з таймаутом 100 мс).
2. **Wi-Fi ініціалізований назавжди, лише `start`/`stop` на спробу** — швидший старт (≈ секунда), але стек і буфери лишаються в памʼяті.
3. **Подія від `control` (повідомлення задачі при вході в DISARMED) замість опитування стану** — швидше й без періодичного опитування, але вводить залежність `drive` → `report` і новий виклик у гарячому шляху; автомат станів колбеків не має.

## Decision outcome

**Chosen:** варіант 1. `esp_netif` і цикл подій створюються один раз при старті задачі (лічені кілобайти), а самі буфери Wi-Fi створюються й повністю звільняються на спробу; повернення памʼяті перевіряється `status`. Ліміти (пропозиція агента, spec A21): підключення Wi-Fi ≤ 15 с, TLS+MQTT ≤ 10 с, усього ≤ 30 с. Задача запускається подією «вхід у DISARMED» (опитування стану раз на 100 мс) і командою консолі. Видалення відправленого звіту з NVS виконується після вимкнення Wi-Fi.

## Consequences

**Positive**
- Радіо фізично вимкнене в усіх станах, крім DISARMED; повернення памʼяті доводиться.
- Затримки мережі не торкаються жодної періодичної задачі.

**Negative**
- Кожна спроба платить повним підключенням (кілька секунд) і не бачить зміну стану швидше за 100 мс.
- Wi-Fi біля приймача ELRS 2.4 ГГц може погіршити радіоканал пульта в DISARMED (ризик у SAD §11).

**Neutral**
- Перехід на варіант 2 пізніше можливий, якщо часу підключення виявиться забагато (змінюється лише `report_hal`).
